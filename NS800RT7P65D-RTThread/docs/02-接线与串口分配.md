# 接线与串口分配

本文件是所有引脚与串口的**唯一权威说明**。引脚号以厂商 SDK 的 `GPIO_xx` 编号表示，
换算规则：**`GPIO_xx` = 端口序号 × 32 + 引脚序号**（PA=0、PB=1、PC=2…）。
例：`GPIO_12` = PA12，`GPIO_38` = PB6，`GPIO_68` = PC4（与 BSP 的 `board.h`、`main.c` 注释一致）。

---

## 一、串口分配（重要：官方 BSP 的控制台与舵机抢 UART1）

### 1.1 冲突的由来

| 用途 | 谁用 | 引脚 |
| --- | --- | --- |
| 官方 BSP 默认控制台 | RT-Thread 控制台 / msh | **UART1：PA12(TX)/PA13(RX)** |
| 本项目总线舵机 | 3 路总线舵机 | **UART1：PA12/PA13**（与你裸机版的接线一致） |

两者都要占用 PA12/PA13，而 BSP 的 `drv_uart.c` 里 UART1 的引脚是**写死**的，
不能在 menuconfig 里改。因此必须二选一错开。

### 1.2 方案 A（默认，推荐）：舵机留 UART1，控制台挪到 UART3

| 串口 | 引脚 | 波特率 | 用途 |
| --- | --- | --- | --- |
| UART1 | PA12 / PA13 | 115200 | **总线舵机**（与现有接线完全一致，不用改线） |
| UART2 | PB6 / PB7 | 115200 | **K230 视觉节点** |
| UART3 | **PB24 / PB25** | 115200 | **控制台**（外接 USB-TTL 到电脑） |

需要做的改动：

```c
// ns800rt7p65-nssinepad/rtconfig.h
#define RT_CONSOLE_DEVICE_NAME "uart3"
```

```c
// applications/app_config.h
#define APP_SERVO_ON_UART3      0     ← 保持默认
```

**接线**：把 USB-TTL 的 RX 接 **PB24**（MCU 的 TX）、TX 接 **PB25**，GND 共地。
这样舵机总线保持原样，控制台另走一路。

> 优点：不用动机器人本体线束；缺点：演示时要多一个 USB-TTL 模块。

### 1.3 方案 B：控制台留 UART1（用板载 USB 转串口），舵机改接 UART3

| 串口 | 引脚 | 波特率 | 用途 |
| --- | --- | --- | --- |
| UART1 | PA12 / PA13 | 115200 | 控制台（板载 USB 转串口） |
| UART2 | PB6 / PB7 | 115200 | K230 |
| UART3 | **PB24 / PB25** | 115200 | 总线舵机 |

```c
// rtconfig.h 保持默认
#define RT_CONSOLE_DEVICE_NAME "uart1"
```

```c
// applications/app_config.h
#define APP_SERVO_ON_UART3      1     ← 改成 1
```

**接线**：把舵机总线的 TX/RX 从 PA12/PA13 改接到 **PB24/PB25**（注意舵机 TX → PB25、
舵机 RX → PB24，即交叉连接）。

> 优点：控制台用板载 USB 口，接线最省事；缺点：要改机器人本体线束。

### 1.4 方案对比

| | 方案 A | 方案 B |
| --- | --- | --- |
| 改线束 | 不用 | 要（舵机从 PA12/PA13 → PB24/PB25） |
| 演示需要 | 额外一个 USB-TTL | 只要一根 USB 线 |
| 与裸机版接线一致性 | ✅ 完全一致 | ❌ 舵机改线 |
| 适用场景 | **保持原车不动、评委看原系统** | 重新布线、只带一块板 |

## 二、完整引脚表

| 功能 | GPIO_xx | 物理引脚 | 方向 | 复用/外设 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 步进 PUL | `GPIO_2` | PA2 | 输出 | GPIO | 脉冲 |
| 步进 DIR | `GPIO_3` | PA3 | 输出 | GPIO | 方向 |
| 步进 ENA | `GPIO_4` | PA4 | 输出 | GPIO | **低有效**（低=使能） |
| 超声波 TRIG | `GPIO_5` | PA5 | 输出 | GPIO | 10µs 高电平触发 |
| 直流电机 NSLEEP | `GPIO_8` | PA8 | 输出 | GPIO | 高电平唤醒驱动器 |
| 直流 PWM A | （BSP 固定） | PA0 | 输出 | **EPWM1 A**（ALT1） | 正转 |
| 直流 PWM B | （BSP 固定） | PA1 | 输出 | **EPWM1 B**（ALT1） | 反转 |
| 总线舵机 TX | （BSP 固定） | PA12 | 输出 | **UART1 TX**（ALT6） | 方案 A |
| 总线舵机 RX | （BSP 固定） | PA13 | 输入 | **UART1 RX**（ALT6） | 方案 A |
| 振动电机 | `GPIO_14` | PA14 | 输出 | GPIO | 高电平开 |
| 超声波 ECHO | （ECAP 配置） | PA16 | 输入 | **ECAP1**（XBAR INPUT7，ALT0） | 必须接 PA16 |
| K230 RX（收） | （BSP 固定） | PB6 | 输出 | **UART2 TX**（ALT1） | 接 K230 的 RX |
| K230 TX（发） | （BSP 固定） | PB7 | 输入 | **UART2 RX**（ALT1） | 接 K230 的 TX |
| 控制台（方案 A） | （BSP 固定） | PB24 | 输出 | **UART3 TX**（ALT11） | 接 USB-TTL RX |
| 控制台（方案 A） | （BSP 固定） | PB25 | 输入 | **UART3 RX**（ALT11） | 接 USB-TTL TX |
| 舵机（方案 B） | （BSP 固定） | PB24 | 输出 | **UART3 TX**（ALT11） | 舵机 RX |
| 舵机（方案 B） | （BSP 固定） | PB25 | 输入 | **UART3 RX**（ALT11） | 舵机 TX |

> 表中「BSP 固定」表示这些引脚在 `bsp/novosns/ns800/libraries/HAL_Drivers/drivers/`
> 的 `drv_uart.c` / `drv_epwm.c` / `drv_ecap.c` 里是写死的，应用层不配置。

## 三、与 K230 的接线

| K230 | 方向 | NS800RT7P65D |
| --- | --- | --- |
| GPIO3（UART1 TX） | → | PB7（UART2 RX） |
| GPIO4（UART1 RX） | ← | PB6（UART2 TX） |
| GND | — | GND |

- 波特率 **115200 8N1**，双向。
- **必须共地**，否则偶发丢字节。
- K230 侧用的 UART1 是它自己板子上的 GPIO3/GPIO4（见 [`../../K230/README.md`](../../K230/README.md)）。

## 四、供电与共地

| 部件 | 供电 | 注意 |
| --- | --- | --- |
| NS800RT7P65D 板 | 5V（USB 或外部） | — |
| 总线舵机 ×3 | **独立 5~7.4V** | 峰值电流大，**不要**从 MCU 板取电 |
| 步进驱动器 | 按驱动器规格 | 与 MCU 共地 |
| 直流电机（吹风） | 按驱动器规格 | 与 MCU 共地 |
| 振动电机 | 按规格 | 建议加续流二极管 |
| 超声波模块 | 5V | ECHO 输出 5V 电平，PA16 是否耐 5V 请核对数据手册（必要时加分压） |
| USB-TTL（方案 A） | USB | GND 与板子共地，**电平选 3.3V** |

> ⚠️ 所有外设的 GND 必须与 MCU 共地，这是联调阶段最常见的故障原因。

## 五、引脚冲突自查

| 冲突点 | 说明 |
| --- | --- |
| PA12/PA13 | UART1：**控制台与舵机只能留一个**（见第一节） |
| PB24/PB25 | UART3：方案 A 作控制台、方案 B 作舵机 |
| PB14/PB15 | 未使用；但注意 BSP 的 `BOARD_LED1_PIN = GPIO_68(PC4)`、`BOARD_KEY_PIN = GPIO_41(PB9)` 若被 `board.c` 初始化，请不要复用 |
| PA0/PA1 | EPWM1，被直流电机占用 |
| PA14 | 作 GPIO 开关用；若改用 EPWM8 做强度调节则不能再当普通 IO |
| PA16 | ECAP1 输入；同时是 EPWM9 A 的复用脚，**不要同时开 `BSP_USING_EPWM9`** |
