# 验收演示脚本

用于向评委演示「**指定主控 NS800RT7P65D 的 RT-Thread 版本已落实**」。
按顺序执行即可，每一步都给出**预期现象**与**失败时的排查方向**。

> ⚠️ **说明**：下列「预期现象」是**按代码逻辑推导**的结果，尚未在实物上逐条验证
> （开发板未到货）。正式演示前请先跑一遍，把实际现象记录在本文件末尾的「实测记录」里；
> 若与预期不符，按「排查」列处理。**不要把未验证的日志当成实测结果对外宣称。**

## 一、启动自检（约 10 秒）

**操作**：给 MCU 上电，观察控制台。

**预期输出**：

```
============================================================
  花卉授粉机器人 · 执行端（RT-Thread 版）
  MCU : NS800RT7P65D (Cortex-M7, 双核)
  OS  : RT-Thread 5.x.x
  编译: <日期> <时间>
------------------------------------------------------------
  K230 指令串口 : uart2 @ 115200 8N1
  总线舵机串口  : uart1 @ 115200 8N1
  指令协议      : one / two / three 选模式，"角度,Y" 执行作业
============================================================
[I/app.servo] 舵机总线就绪: uart1 @ 115200
[I/app.step] 步进电机就绪: PUL/DIR/ENA = GPIO_2/GPIO_3/GPIO_4 (PA2/PA3/PA4)
[I/app.dc] 直流电机就绪: epwm1 A/B 通道, 20kHz
[I/app.vib] 振动电机就绪: GPIO_14 (PA14)
[I/app.us] 超声波就绪: TRIG=PA5, ECHO=PA16(ECAP1), 计数时钟 200 MHz
[I/app.ctrl] 业务层启动完成: K230 串口 uart2 @ 115200

[main] 系统就绪，等待 K230 下发指令...
msh >
```

**这一步同时回答了评委的第一个问题**：屏幕上明确显示 `RT-Thread` + `msh`，
说明这不是裸机程序。

**排查**：
- 没有任何输出 → 控制台串口接错（方案 A 是 PB24/PB25，不是 PA12/PA13）、波特率不是 115200、或 USB-TTL 电平不对
- 有 banner 但某一行是 `[E/...] 初始化失败` → 对应外设没在 menuconfig 打开，或引脚被其它功能占用

## 二、状态总览

**操作**：在 `msh >` 输入

```
status
```

**预期输出**：

```
── 执行端状态 ──
  作业模式 : 未选择
  动作线程 : 空闲
  步进角度 : 0°
  直流电机 : 0%
  振动电机 : 关
  测距系数 : 1.000
  舵机串口 : uart1
  K230 串口: uart2
```

**讲解要点**：这些状态由两个线程共享（rx 线程改模式、动作线程改角度/忙碌标志），
体现 RT-Thread 的多线程与 IPC。

## 三、整机上电自检（一键驱动全部执行器）

**操作**：

```
selftest
```

**预期现象**（按顺序，约 15 秒）：

| 步骤 | 现象 |
| --- | --- |
| 1/6 | 三路舵机依次"上电"（能听到轻微上电声，舵机轴变硬） |
| 2/6 | 舵机 1 转到 400、舵机 2 转到 600 再回 400、舵机 3 伸到 1000 再回 0 |
| 3/6 | 振动电机转 1 秒 |
| 4/6 | 控制台打印 `[4/6] 测距 = xx.x cm` |
| 5/6 | 直流电机（吹风）50% 转 1 秒 |
| 6/6 | 步进电机正转 10° 再回 0° |

结束时打印 `=== 自检结束 ===`。这一步对应裸机版 `System_Init()` 里的上电自检流程，
用来证明**所有执行器都已被 RT-Thread 驱动起来**。

**排查**：舵机不动 → 舵机电源/总线极性；步进不转 → ENA 电平、驱动器使能方式；
超声为 0 → PA16 接线或用 `dist 5` 看原始计数。

## 四、逐模块单独演示（评委可点名任意一项）

| 命令 | 预期现象 | 说明 |
| --- | --- | --- |
| `servo 1 350 1000` | 1 号舵机 1 秒内转到 350 位置 | 直接验证总线舵机 |
| `servo 3 1000 1000` | 伸缩机构伸出到最大 | 伸缩行程 |
| `step 30` | 步进电机转到 30°，控制台打印 `步进: 0° → 30°（400 脉冲）` | 水平定位 |
| `step 0` | 回到 0° | |
| `dc 60` | 吹风电机 60% 转速 | 注意会一直转，用 `dc 0` 停 |
| `dc -60` | 反向转 | 验证 H 桥换向 |
| `vib 1000` | 振动 1 秒后自动停 | |
| `dist 5` | 连续打印 5 次 `距离 = xx.x cm, 原始计数 = xxxxx` | 超声波 |
| `us_cal 0.99` | 校准系数改为 0.990 | 现场标定用 |

> `dist` 的「原始计数」是关键调试信息：**计数非 0 但距离不对**说明换算系数要校，
> **计数为 0** 说明根本没收到底层回波（接线/触发问题）。

## 五、K230 联调（完整指令链路）

### 5.1 没有 K230 时：用 PC 模拟

把 USB-TTL 接到 **PB7（MCU 的 UART2 RX）**、GND 共地，用一个串口工具发 ASCII 指令（**不发换行也可以，但发了更稳**）：

| 发送内容 | 预期回复 | 说明 |
| --- | --- | --- |
| `30,120` | `noMode` | **没选模式**时的保护，证明协议校验生效 |
| `one` | （无回复，控制台打印 `作业模式 → 振动(one)`） | 选择模式 |
| `30,120` | 约 10 秒后 `workOK` | 完整作业 |
| `two` 然后 `0,80` | 风吹 3 秒，最后 `workOK` | 吹风模式 |
| `three` 然后 `-20,150` | 伸缩到位，最后 `workOK` | 触摸模式，负角度验证反向 |

Python 模拟脚本（需要 `pip install pyserial`）：

```python
import serial, time

ser = serial.Serial("COM5", 115200, timeout=0.2)   # 改成你的 USB-TTL 端口

def send(text, wait=0.3):
    print(">>", text)
    ser.write((text + "\n").encode())
    time.sleep(wait)
    print("<<", ser.read(256).decode(errors="replace").strip())

send("30,120")    # 预期 noMode
send("one")       # 选模式
send("30,120", 12)  # 预期约 10 秒后 workOK
send("two")
send("0,80", 8)
ser.close()
```

### 5.2 接上 K230 后：MQTT 触发全链路

1. K230 上电，通过 MQTT 订阅指令主题（见 [../../K230/README.md](../../K230/README.md)）；
2. 手机/电脑向该主题发 `1` → K230 通过 UART1 向执行端连发 4 次 `one\n`；
3. 执行端控制台打印 `作业模式 → 振动(one)`；
4. K230 识别到目标后发坐标（`角度,Y\n`）；
5. 执行端打印 `=== 开始作业 ... ===` → 各动作 → `=== 作业完成，已回复 workOK ===`；
6. K230 侧收到 `workOK`，继续下一轮。

**演示话术**：这条链路把「云端指令 → 视觉识别 → 串口协议 → RT-Thread 执行端多线程动作」
完整串起来，其中执行端在跑 RT-Thread。

## 六、演示现场可能被问到的问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么用 RT-Thread 而不是裸机？ | 指定主控要求 RT-Thread；改造后动作线程阻塞不影响收指令，模式指令可即时生效，且可用 msh 现场调试 |
| 你用了哪些 RT-Thread 机制？ | 线程（rx / 动作）、消息队列（坐标排队）、信号量（串口接收、超声捕获）、互斥量（舵机总线）、设备框架（uart / pin / pwm）、msh |
| 驱动都是你自己写的吗？ | UART/PIN/PWM 用官方 BSP 的设备驱动；总线舵机、步进、超声捕获、业务时序是自己实现的（见移植对照表） |
| 超声波为什么不用 BSP 的 ecap 驱动？ | BSP 的驱动固定为连续 4 边沿捕获，单次回波凑不齐事件；所以直接配 ECAP1 单次捕获（文档里有说明） |
| 和裸机版有什么区别？ | 功能、时序、协议完全一致，差异在调度方式；详见 `docs/01-移植对照表.md` |
| 怎么证明没跑裸机？ | 控制台 `msh >` 提示符、`version` / `list_thread` / `free` 等 msh 命令（BSP 已开 `RT_USING_FINSH`） |

## 七、故障预案

| 万一 | 现场处理 |
| --- | --- |
| 控制台没输出 | 换 USB-TTL 端口/线，确认接的是 PB24/PB25，波特率 115200 |
| 某一路舵机不响应 | 先用 `servo <id> 500` 确认，再检查该舵机 ID 与供电；演示时避开这一路 |
| 超声一直 0 | 直接在 `dist` 命令下用尺子测实际距离做对比讲解，并说明可用 `us_cal` 校准 |
| K230 侧没反应 | 退到 5.1 的 PC 模拟，证明执行端本身没问题 |
| 动作超时/队列满 | 控制台会打印 `动作队列已满，丢弃指令`，说明可 `status` 查看是否 `执行中` |
