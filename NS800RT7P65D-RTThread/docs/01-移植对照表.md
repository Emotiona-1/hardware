# 裸机版 → RT-Thread 版 移植对照表

左列是 [`../../NS800RT7P65D/`](../../NS800RT7P65D/README.md)（裸机版，厂商 StdDriver + 主循环），
右列是本目录的实现。**行为与时序保持一致**，差别只在「怎么把硬件驱动起来」。

---

## 一、文件级对照

| 裸机版文件 | RT-Thread 版文件 | 变化程度 |
| --- | --- | --- |
| `User/main.c` | `applications/main.c` + `app_control.c` | 主循环拆成 rx 线程 + 动作线程 |
| `Hardware/Control.c/.h` | `applications/app_control.c/.h` | 协议与时序不变，改为队列驱动 |
| `Hardware/Servo.c/.h` | `applications/app_servo.c/.h` | 报文不变，串口改用设备框架 |
| `Hardware/motor.c/.h` + `track.c/.h` | `applications/app_stepper.c/.h` | 合并为一个模块，脉冲用 `rt_hw_us_delay` |
| `Hardware/PWM.c/.h` + `DCMotor.c/.h` | `applications/app_dcmotor.c/.h` | 直写 EPWM 寄存器 → `rt_pwm_*` |
| `Hardware/vibration_motor.c/.h` | `applications/app_vibration.c/.h` | 只保留 GPIO 开关模式 |
| `Hardware/Ultrasonic.c/.h` | `applications/app_ultrasonic.c/.h` | ECAP 配置不变，忙等改为信号量 |
| `Hardware/Serial.c/.h` | BSP 的 `drv_uart.c` + `app_control.c` | 中断收发改由 BSP + 应用层处理 |
| `Hardware/delay.c/.h` | RT-Thread 内核 + `rt_hw_us_delay` | 毫秒用内核延时 |
| `Hardware/LED.c/.h`、`Key.c/.h`、`OLED.c/.h` | **未移植** | 裸机版 `main.c` 也未调用，属预留代码 |
| `User/ns800rt7p65d_it.c` | BSP 的启动文件 + `board.c` | 中断向量由 BSP 接管 |

## 二、API 级对照

### 2.1 系统与延时

| 裸机版 | RT-Thread 版 | 备注 |
| --- | --- | --- |
| `Device_init()` | BSP `rt_hw_board_init()` 内完成 | 应用层不再调用 |
| `Device_unlockPeriphReg()` | 同上 | |
| `Interrupt_initModule()` / `Interrupt_initVectorTable()` | 同上 | |
| `delay_init()` | 内核 SysTick（`RT_TICK_PER_SECOND=1000`） | |
| `Delay_ms(n)` | `rt_thread_mdelay(n)` | **让出 CPU**，其它线程可运行 |
| `delay_us(n)` / `Delay_us(n)` | `rt_hw_us_delay(n)` | 仍是忙等，用于脉冲/触发宽度 |

### 2.2 串口

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `Serial2_Init()`（PA12/PA13 复用 UART1、PB6/PB7 复用 UART2） | BSP `drv_uart.c` 按 `BSP_USING_UARTx` 自动完成 |
| `Serial2_GetRxFlag()` 轮询 | `rt_device_set_rx_indicate()` + 信号量 |
| `Serial2_GetRxData()` | `rt_device_read()` 批量读 |
| `Serial2_SendString()` | `rt_device_write()` |
| 裸机版里 UART1 只有舵机用 | 舵机 = `uart1`（或 `uart3`），K230 = `uart2`，控制台 = 另一个 UART |

### 2.3 舵机

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `SERVO_Init()`（手工配 PA12/PA13、`UART_setBaud`） | `app_servo_init()` → `rt_device_find("uart1")` + `rt_device_open` + `RT_DEVICE_CTRL_CONFIG` |
| `SERVO_SendPacket()`（逐字节写 `UART_writeChar`） | `app_servo_send_cmd()` → 组包后一次 `rt_device_write()` |
| `SERVO_CalcChecksum()` | 相同算法（负载字节求和取反） |
| `SERVO_MoveTimeWrite()` | `app_servo_move_time()` |
| — | 新增互斥量 `s_servo_lock`，防止多线程写总线交错 |

### 2.4 步进电机

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `Motor_Init()`（GPIO 配为输出） | `app_stepper_init()` → `rt_pin_mode(PIN_MODE_OUTPUT)` |
| `Motor_Enable()` / `Disable()` | `app_stepper_enable()`（ENA 低有效，与原来一致） |
| `Motor_SetDirection()` | `app_stepper_set_dir()` |
| `Motor_OnePulse()` / `_Slow()` | `app_stepper_run_steps()` 内部实现（50µs / 600µs） |
| `Motor_RunSteps()` / `_Slow()` | `app_stepper_run_steps(steps, slow)` |
| `Motor_TrackX()`（`track.c`） | `app_stepper_track_x()`，换算系数不变：`1600/360 × 3` |

### 2.5 直流电机 / PWM

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `PWM_Init()`（EPWM1、20kHz、UP 计数） | BSP `drv_epwm.c`，menuconfig 打开 `BSP_USING_EPWM1` |
| `PWM_SetCompare3(v)` / `SetCompare4(v)`（0~100） | `rt_pwm_set(dev, 0/1, period_us, pulse_us)` |
| `DCMotor_SetSpeed(±100)` | `app_dcmotor_set_speed(±100)`，逻辑相同（正转走 A 路，反转走 B 路） |
| `DCMotor_Init()`（NSLEEP 拉高） | `app_dcmotor_init()` → `rt_pin_write(NSLEEP, PIN_HIGH)` |

> ⚠️ **单位差异**：本 BSP 的 `period` 按**微秒**解释（`drv_epwm.c`：
> `signal_freq = 1 / (period / 1e6)`），与 RT-Thread 文档中「纳秒」的惯例不同。
> 20kHz 对应 `APP_PWM_PERIOD_US = 50`。

### 2.6 振动电机

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `VibrationMotor_Init()` / `On()` / `Off()` / `Toggle()` | 同名的 `app_vibration_*()`，改用 `rt_pin_write()` |
| `VibrationMotor_Vibrate(ms)` | `app_vibration_pulse(ms)` |
| `VibrationMotor_PWM_Init()` / `SetIntensity()`（EPWM8） | **未移植**（裸机版 `main.c` 也未调用；如需要可按 2.5 的方式用 `epwm8`） |

### 2.7 超声波

| 裸机版 | RT-Thread 版 |
| --- | --- |
| `Ultrasonic_Init()`（ECAP1 单次捕获、XBAR INPUT7、PA16） | `app_ultrasonic_init()`，**寄存器配置完全相同** |
| `Ultrasonic_Echo_Isr()` | `us_ecap_isr()`，外加 `rt_interrupt_enter/leave()` 并在其中 `rt_sem_release()` |
| `while (capture_state < 2) { Delay_us(1); }` 忙等 | `rt_sem_take(&s_us_done, 超时)`，**带超时不再死等** |
| `__disable_irq()` / `__enable_irq()` | `rt_hw_interrupt_disable()` / `rt_hw_interrupt_enable()` |
| `(falling - rising) / ticks_per_us / 58` | 同一公式，另加可调系数 `us_cal` |

### 2.8 业务逻辑

| 裸机版 `Control.c` | RT-Thread 版 `app_control.c` |
| --- | --- |
| `Control_MainLoop()` 主循环取字节 | `rx_thread_entry()` 信号量唤醒后批量读 |
| 行缓冲 32 字节、`\n`/`\r` 分割 | 相同（`APP_RX_LINE_MAX = 32`） |
| `Control_ProcessLine()`：`one`/`two`/`three` 改 `s_mode` | 相同，但**立即生效**（不等当前动作） |
| `sscanf("%hd,%hd")` 解析坐标 | 手写 `strtol` + `strchr` 解析（不依赖 `sscanf`） |
| `Control_OnCoordinate()` 顺序执行 | `action_execute_coordinate()`，顺序与时序不变 |
| `Control_ReturnHome()` | `action_return_home()`，延时值不变 |
| `Serial2_SendString("workOK")` | `app_control_reply(APP_REPLY_WORK_OK)` |
| 队列不存在（处理不过来就丢） | 消息队列深度 8，满了回 `busy` |

## 三、时序对照（逐项不变）

| 步骤 | 裸机版 | RT-Thread 版 |
| --- | --- | --- |
| 姿态到位后等待 | `Delay_ms(3000)` | `rt_thread_mdelay(APP_ARM_SETTLE_MS=3000)` |
| 作业前准备 | `Delay_ms(2000)` | `APP_MODE_PREPARE_MS=2000` |
| 振动持续 | `Delay_ms(1000)` | `APP_VIBRATE_ON_MS=1000` |
| 吹风 | 100% × 3000ms | `APP_BLOW_DUTY_PCT=100` × `APP_BLOW_ON_MS=3000` |
| 伸缩舵机 | 1000ms 运动 + 5000ms 保持 | `APP_TELESCOPIC_MOVE_MS` / `APP_TELESCOPIC_HOLD_MS` |
| 回原点各处等待 | 2000ms ×3 | `APP_HOME_WAIT_MS=2000` ×3 |

## 四、有意为之的行为差异

| 差异 | 原因 | 影响 |
| --- | --- | --- |
| 主循环不再被动作阻塞 | 动作搬到独立线程 | 动作执行期间仍可收指令、可改模式 |
| 模式指令立即生效 | rx 线程直接改 `s_mode` | K230「先发 1/2/3 再发坐标」的流程更可靠 |
| 测距有超时 | 信号量带超时（120ms） | 无回波时不再卡死，返回 0.0 |
| 队列满回 `busy` | 避免上位机死等 | K230 端可据此重发 |
| 动作开始时取模式快照 | 避免动作中途换模式导致半途改变 | 行为可预测 |
| 舵机发送加互斥量 | 多线程安全 | 无副作用 |

## 五、没有移植的部分及原因

| 模块 | 原因 |
| --- | --- |
| `LED.c` / `Key.c` / `OLED.c` | 裸机版 `main.c` 未调用，属预留代码；且 OLED 的 PB14/PB15 与 EPWM4/控制台存在潜在冲突 |
| `VibrationMotor_PWM_Init()` | 作业流程只用开关模式；如需强度调节，可开 `BSP_USING_EPWM8`（PA14） |
| `SERVO_AngleLimitWrite` / `IdWrite` / `SetAngleOffset` 等 | 一次性配置命令，保留在 `app_servo_send_cmd()` 的通用接口里，未单独封装 |
| `Serial1_*`（裸机版里与舵机抢 UART1 的冗余代码） | 本身就是冗余，直接删除 |
